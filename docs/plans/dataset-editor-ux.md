# Редактор датасетов — упрощение для неподготовленных пользователей

Дата: 2026-07-30
Модуль: [`modules/dataset-editor/`](../../modules/dataset-editor/)
Первоисточник по формату: `storyview/docs/plans/dataset-editor-guide.md` (гайд для разработчика от команды LSS)

---

## 1. Диагноз

Редактор сделан как **форма над IR** — промежуточным представлением данных LSS.
Пользователь обязан держать в голове модель: сущность → список грантов → 25 типов →
каналы (числовой / текстовый / ресурсный). Гайд прямо говорит: «редактор сущности =
редактор списка грантов», и это честно реализовано — но это модель *разработчика*,
а не автора хоумбрю. Автор думает «моя раса видит в темноте и даёт +1 к КД», а не
«мне нужен trait с params.range и bonus с target=ac, mode=add».

### Конкретные точки боли

1. **Пустой холст.** `handleCreate` создаёт `{ name: 'Новый датасет' }` и бросает в форму
   метаданных. Первое, что видит человек — два **задизейбленных** поля (Идентификатор,
   Лицензия) равного визуального веса с полезными. Гайд §0: «стройте под ревью импорта,
   а не под пустой холст».
2. **Первая вкладка — Классы.** Самое сложное и наименее выразимое (§2 «экспрессивный
   обрыв»: кости, ячейки, нечисловые правила класса всё равно уйдут прозой). Гайд §7
   рекомендует порядок «расы → предыстории → черты → подклассы → классы».
3. **Слово «грант»** нигде не объяснено кроме тултипа. Дальше — `pairId`, `maxExpr`,
   `expr`, `upgrade/downgrade/multiply`, `casterType: memory/list/book`,
   `progression: full/half/third/pact` (последние два вообще не переведены).
4. **Выбор типа гранта** — плоская сетка из 25 пунктов без поиска, без группировки, без
   описаний. «Характеристики (фикс)» / «(выбор)» / «(пул)» различимы только тому, кто уже
   знает модель.
5. **Смешение языков.** `grantSummary` выдаёт `pick 2 from stealth, arcana`, `30 ft`,
   `3 pts, max 2`, `int / list (full)`. Половина линта на английском
   (`Unknown target "x" — the bonus will not apply. Typo?`), половина на русском. Пути
   вида `classes/blood-hunter@5/grants[2]` показываются как есть и никуда не ведут.
6. **Три разные модели сохранения на одном экране**: метаданные автосохраняются
   (debounce 500 мс), сущность — кнопки Сохранить/Отмена, грант — OK/Отмена. «Отмена»
   в EntityEditor молча выбрасывает всю вложенную работу с грантами.
7. **Ловушки формата не закодированы в UI**, хотя гайд их перечисляет:
   - `max` XOR `maxExpr` — сделано двумя соседними опциональными инпутами; §5.8 явно
     требует переключатель «число / формула».
   - `bonus`: `value` XOR `expr` — та же ошибка, тот же паттерн.
   - §5.10: числовые гранты внутри `feat` **не разворачиваются** — хоумбрю-черта «+1 к КД»
     уезжает в тишину. Ни линта, ни подсказки в форме.
   - Свободный ввод формул (`[f:...]`, `expr`, `maxExpr`) — §5.3 просит этого не делать.
8. **Нет предпросмотра.** Автор ни разу не видит, что получится на листе. Модель каналов
   невидима: что описание черты с `params` потеряется, узнаёшь только из линта постфактум.
9. **Опасные операции без подтверждения.** Trash в `DatasetList` удаляет весь датасет
   мгновенно и безвозвратно (у сущности подтверждение есть — непоследовательно).
   `localStorage` при переполнении падает молча (`storage.ts`).
10. **Разнобой в глоссарии** внутри одного инструмента: ExtractPanel — «Фоны»/«Фиты»,
    EntityList — «Предыстории»/«Черты», DatasetList — «предысторий»/«черт».
11. **Мелочи, читающиеся как небрежность**: «Нет классы», «отобразиться» без мягкого
    знака, поле «Английское название» даёт английский `label`, который потом надо руками
    переписывать на русский.
12. **Нет поиска/фильтра** в списке сущностей — на датасете из 80 черт это стена.
13. **Нет выхода наружу как явного шага.** Экспорт — иконка 15px в карточке. Гайд §7:
    «без пути наружу редактор бессмысленен».

## 2. Предложения

### A. Онбординг и точка входа

- **A1. Убрать пустой холст.** Экран «Создать» → выбор сценария: «Хоумбрю-раса» /
  «Хоумбрю-черта» / «Подкласс к SRD-классу» / «Предыстория» (создают датасет с уже
  заведённой сущностью нужного вида), «Импортировать JSON», «Начать с примера»
  (предзаполненный датасет-образец), и лишь последним — «Пустой датасет».
- **A2. Шаблоны сущностей.** При добавлении расы/черты предлагать скелет: раса уже с
  `speed 30`, `size medium`, слотом под тёмное зрение; черта происхождения — с
  `category: origin`. Сейчас `makeEmptyEntity` даёт голый объект.
- **A3. Переставить вкладки** в порядке гайда §7: Расы → Предыстории → Черты → Подрасы →
  Подклассы → Классы. У вкладки «Классы» — честная плашка: «класс механизируется
  частично: кости и нечисловые правила уйдут текстом».
- **A4. Первый запуск** — три карточки поверх пустой библиотеки: «Что такое датасет» /
  «Соберите первую расу за 5 минут» / «Как подключить готовый датасет в LSS».

### B. Информационная архитектура

- **B1. Свернуть метаданные.** ID и Лицензия — не поля ввода, а мелкая строка-подпись под
  названием (`pq-dedc… · CC-BY-SA-4.0`) с тултипом. На первом экране остаются Название,
  Автор, Редакция; Версия — в блок «Публикация» (H2).
- **B2. Двухпанельный режим для редактирования.** Слева дерево датасета, справа форма.
  Сейчас навигация — стек полноэкранных состояний (`library → edit → entity → grant`)
  с потерей контекста на каждом шаге.
- **B3. Поиск и фильтр** в списке сущностей + фильтр «только с ошибками».
- **B4. Merge/Extract убрать с верхнего уровня** в меню «…» карточки датасета — это
  операции для того, у кого уже 3+ датасета.

### C. Язык и терминология

- **C1. Отказаться от слова «грант» в интерфейсе.** «Что это даёт персонажу»,
  «Добавить эффект», «Что открывается с уровнем». Слово «грант» — только в тултипе,
  для тех, кто полезет в JSON.
- **C2. Единый глоссарий** одним модулем: предыстории (не фоны), черты (не фиты),
  вид/раса — выбрать одно.
- **C3. Дописать переводы**: `full/half/third/pact`, `memory/list/book`, категории черт
  в GrantEditor.
- **C4. Локализовать `grantSummary` и линт** — единым тоном «что сломается на листе», как
  уже сделано в новых правилах (`resource-*`, `numeric-trait-prose`).
- **C5. Починить склонения** («Нет классы») — словарь форм для видов сущностей.

### D. Выбор эффекта — от намерения, а не от типа

Вместо сетки из 25 типов — **пикер с поиском и группами по смыслу**:

```
🔍 [ поиск: "темнов…" ]

Характеристики      →  Фиксированный бонус · Выбор игрока · Пул очков
Владения            →  Навыки · Инструменты · Языки · Оружие · Броня · Спасброски
Способности         →  Описание способности · Счётчик использований · Чувство
Боевое              →  Скорость · Кость хитов · Бонус к чему-либо
Старт персонажа     →  Снаряжение · Золото · Черта
Развилки            →  Выбор одного из вариантов
```

Каждый пункт — со строкой «что это сделает на листе». Поиск по синонимам: «темновидение»,
«дарквижн» → «Чувство: тёмное зрение»; «ярость», «очки» → «Счётчик использований».

Плюс **быстрые рецепты**: «+2 к одной характеристике», «владение двумя навыками на выбор»,
«способность N раз между отдыхами» — одна кнопка создаёт сразу правильную пару грантов
(`trait` + `resource` со связанным `pairId`, что §5.8 называет главной ловушкой формы).

### E. Защитные ограждения (кодируем гайд в UI)

- **E1. `max`/`maxExpr` и `value`/`expr` — переключатель «Число ⇄ Формула»**, а не два поля.
  Убирает два самых частых error’а линта до их появления.
- **E2. Конструктор формул** вместо текстового поля (§5.3): выпадашки `[LVL]`, `[PROF]`,
  `[HALF_PROF]`, `[STR]…[CHA]` + плоская арифметика, с предпросмотром «на 5 уровне = 3».
  Свободный ввод — за флажком «продвинутый режим».
- **E3. Предупреждение при числовых грантах внутри черты** (§5.10) — новое правило линта:
  «числовые эффекты внутри черты не доезжают до листа, перенесите на вид/класс/предысторию».
- **E4. Форма ресурса ведёт за руку**: сначала «к какой способности относится счётчик»
  (выбор из черт сущности + кнопка «создать описание»), потом максимум, потом отдых.
- **E5. Мягкие подтверждения**: удаление датасета через confirm + тост «Отменить».
- **E6. Реакция на переполнение localStorage** вместо `catch {}`.

### F. Живой предпросмотр — главный рычаг понимания

Панель «Как это выглядит на листе» рядом с формой: слайдер уровня 1–20 и рендер того, что
сущность реально даёт — числа, текстовые блоки, счётчики, по каналам. Тогда видно:
пропавшее описание черты с `params` (§5.5), работу `leveledGrants`, мёртвый таргет `bonus`.
Дорого, но объясняет модель без единого слова документации. Даже упрощённый вариант
(«сводка эффектов текстом») даёт большую часть пользы.

### G. Линт как помощник, а не лог компилятора

- **G1. Кликабельные ошибки**: `classes/blood-hunter@5/grants[2]` → «Кровавый охотник →
  уровень 5 → эффект №3», по клику открывается нужная форма.
- **G2. Группировка по сущностям** вместо плоского списка.
- **G3. Быстрые фиксы**: «Убрать expr» / «Поставить pairId: null» / «Создать описание».
- **G4. Разделить «ошибка» и «предупреждение» по смыслу для автора**: «не поедет на лист»
  vs «поедет, но не туда».
- **G5. Зелёное состояние**: «Замечаний нет — датасет готов к выгрузке».

### H. Модель сохранения и безопасность работы

- **H1. Один режим сохранения** везде (автосохранение либо явное) — сейчас три.
- **H2. Черновик / опубликовано** (§5.2 — гайд называет это не опцией, а единственным
  барьером, пока в LSS нет версионирования): «Опубликовать» бампает `version`, показывает
  диф с прошлой публикацией и предупреждает «у всех, кто уже взял эти сущности, числа
  изменятся».
- **H3. История версий в localStorage** (последние N снапшотов) + «Откатить».
- **H4. Бэкап**: «Выгрузить все датасеты одним файлом» / «Восстановить».

### I. Документация и обучение

- **I1. Страница `/lss/dataset-editor/guide`** — авторский гайд (не для разработчиков):
  что такое датасет, что такое эффект, что механизируется, а что уезжает текстом и почему
  это нормально (§2 «частичная механизация — это продукт, а не провал»).
- **I2. Кукбук рецептов**: «Раса с тёмным зрением», «Черта с использованиями раз в короткий
  отдых», «Подкласс к SRD-воину», «Экспертиза на навык» (§5.9), «Снаряжение или золото».
  Каждый — 5 скриншотов и готовый JSON.
- **I3. «Почему это не работает»** — FAQ, зеркалящий правила линта: раздел на правило,
  пример до/после.
- **I4. Контекстные «Подробнее»** в тултипах — ссылка на раздел гайда вместо стены текста
  в окошке 224px.
- **I5. Короткие GIF-ки** в пустых состояниях.
- **I6. Глоссарий-панель** — выдвижная шпаргалка «эффект / сущность / id / датасет / канал».

### J. Импорт как основной сценарий (совет гайда №1)

Гайд утверждает: главный экран — **не создание, а ревью импорта**. Dimension Door научится
тянуть классы/расы и начнёт выдавать черновики с ошибками; редактор ценен как мастерская
починки черновиков.

- **J1. Режим «починить импорт»**: после импорта не карточка «OK», а пошаговый проход по
  замечаниям («3 места требуют внимания» → Далее → Далее).
- **J2. Вставка из текста**: копируем статблок с dnd.su → черновик сущности (заголовок →
  label и id-слаг, «Скорость 30 футов» → грант скорости). Даже примитивный парсер по
  ключевым фразам снимает основную массу ручного ввода.
- **J3. Диф при повторном импорте** того же id — вместо `window.confirm` на английском.

### K. Замыкание цикла

- **K1. Явный шаг «Готово»**: «Скачать JSON» + инструкция «как подключить в LSS» +
  «Проверить, что всё чисто».
- **K2. Шаринг ссылкой** (датасет в URL-хеше или через короткий бэкенд).
- **K3. Витрина** готовых датасетов на pumpkin — решает вопрос «откуда брать контент» и
  даёт новичку живой пример для разбора.

### L. Дешёвые быстрые победы

- «Нет классы» → «Здесь пока пусто».
- Локализовать `grantSummary` и старые сообщения линта.
- Дописать переводы `full/half/third/pact`, `memory/list/book`, категорий черт в GrantEditor.
- Единый глоссарий (фоны/фиты → предыстории/черты).
- Confirm на удаление датасета.
- Свернуть ID и Лицензию в подпись.
- Поиск в списке сущностей и в пикере типов эффектов.
- Поменять порядок вкладок (расы первыми).
- При создании сущности спрашивать два поля сразу: «Название» (рус → `label`) и
  «English name» (→ `id`). Сейчас человек получает английский `label` и правит его вторым
  заходом.
- Опечатка «отобразиться» → «отобразится» в тултипе поля «Предпочтения».

## 3. Приоритет

1. **L целиком** — один заход, снимает ощущение «сырого инструмента». ✅ *сделано 2026-07-30*
2. **A1 + A3** (сценарии вместо пустого холста, расы первой вкладкой) — меняет первую
   минуту, самую дорогую.
3. **D** (пикер эффектов от намерения + рецепты) — снимает главный когнитивный барьер.
4. **G** (кликабельный, русский, группированный линт с быстрыми фиксами) — превращает
   главного врага новичка в помощника.
5. **E1 + E2** (XOR-переключатели и конструктор формул) — убирает целый класс ошибок
   до их появления.

**F (предпросмотр листа)** — самая ценная по объяснительной силе и самая дорогая; сразу
после этой пятёрки. **H2 (черновик/публикация)** — не UX-улучшение, а защита чужих
персонажей; чем раньше у датасетов появятся реальные пользователи, тем дороже её отсутствие.
